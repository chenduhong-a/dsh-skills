# 视觉卡片交付手册

> 场景：要把内容画出来、做成卡、或导出成能带走的 HTML。先定渲染器，再守红线；两块都过关才发。
>
> CSS 技法细节查插件自带文档：`C:\deepseek\插件\dsh-raw-html-v2\DESIGN.md`（字体、禁项、主题变量）、`C:\deepseek\插件\dsh-raw-html-v2\styles\_INDEX.md`（风格命中）。本文件只定判断规则与红线，不重复文档里的技法。
> 另外三份也别漏：`EDITORIAL.md`（图型库）、`FRAMING.md`（长文装帧）、`BREATH.md`（灵魂手册）；字体查 `styles\_FONTS.md`，`_INDEX.md` 没命中风格时按 `_BASELINE.md` 兜底。

## 判据

**先选通道，再读下面的表**：按本节「默认 + 三条升级」判（不写行号——上一版写「第 28 行」，改一次编号就指错）；下表只是各通道的**能力与代价速查，不是选路依据**——它按「这次要做的事」分行，同一件事可能同时落进两行（「三组数据做成对比图」既像静态图表又像可比数据），照表直接挑必挑错。

一张表定去留（速查用）：

| 这次要做的事 | 用哪个 | 判据与代价 |
|---|---|---|
| 静态图表、表格、数据卡、说明卡，想跟正文长在一起 | VCP 裸 HTML | 消息级渲染，随正文流式长出；默认不带脚本，样式锁在本条消息 |
| 要真算、真动、真响应：canvas、逐帧动画、状态机、键盘、小游戏 | `render_visual` | iframe 里脚本真执行；代价是卡在本轮回答下方、本轮结束才出现，且**外壳由宿主决定**（标题栏 + 全屏/复制/下载 + 边框 + 固定高度），里面别再套一层卡片框、不要重复标题、高度给够否则出滚动条——纯展示用它就会「不像正文卡片」 |
| 一堆可比数据：3 行以上的表、趋势与占比、指标数字、进度、可拖的参数、需逐步播放的过程 | `a2ui` | 声明式 A2UI 1.0 JSON + 26 个受控组件，本地排序/悬停/滑块，不写 HTML 也不用自己防流式抖动；代价是样式受组件约束，做不了装帧（纹理、serif、SVG 封面） |
| 想让它以后还能打开：能反复用的页面、面板或小工具 | `personalized-pages` | **不是渲染器而是出口**——走提案流程落成应用里的页面；代价是比我直接发张卡重得多，只为看一眼的内容不值得 |
| 让用户在几个方案里选 | `ask_user_question` | 不是视觉卡；正文先给判据，选项 ≤5、推荐项第一 |
| 要发给别人、离线打开、手机看、打印 | 单文件 HTML | 只有明确要「存档 / 跨设备」才写文件；正文仍要给摘要 |
| 一两句话能说清 | 纯文本 | 不为装饰发卡 |

**默认：VCP 裸 HTML。** 静态装帧、表格、清单、对比、说明——想跟正文长在一起的，一律先按这个走；什么都不命中就用它。它最便宜：消息级渲染、随正文流式长出、不用挑工具。

**只有下面三条之一成立才升级**（其余情况一律留在默认）：

1. **主体是可比数据或可调参数**（≥3 个系列／类别，或 ≥3 行、≥8 个数据点的趋势与占比；指标、进度、滑块）→ `a2ui`。**清单式的多步流程不算**——那是结构不是数据，五步清单仍是清单；要真正逐步播放／动画演示才算。**1–2 个数值也不算**，两个数直接写正文。
2. **要真跑脚本**（计算、逐帧动画、状态机、键盘、小游戏）→ `render_visual`。代价：卡在本轮回答下方、本轮结束才出现，外壳由宿主决定（标题栏 + 全屏/复制/下载 + 边框 + 固定高度），纯展示用它就不像正文卡片。
3. **要留成应用里的页面或小工具**（以后还要反复打开）→ `personalized-pages`——**这是出口，不是渲染器**。

**换形态**：要离开本机（存档、跨设备、打印）→ 单文件 HTML。

**不发卡**：一两句话能说清的事，直接写正文。

三个常见误判：

- 「要动画」不等于「要脚本」：CSS 动画（淡入、轮播）VCP 也能做；只有需要计算、输入、状态机才上 `render_visual`。
- 「要交互」不等于「要自己画控件」：让用户选方案用 `ask_user_question`，不要在卡里手搓选项——radio+label 在 VCP 里点不动。
- 「要好看」不等于「要发卡」：正文里一段结构化的纯文本列表，有时比卡更快被读懂。

**以上都不合适**的场合：用户要的是结论、命令、路径、可复制的长串。这些给纯文本或代码块，塞进卡里只会更难取。

## 前两条通道的细节边界

先认清这是两台不同的渲染器，不是同一套规范的两种写法。

| 维度 | `render_visual`（dsh-visual-card） | VCP 裸 HTML（dsh-raw-html-v2） |
|---|---|---|
| 落点 | 独立窗口，固定在本轮回答**下方**，不能插入正文中间 | 回复正文里的消息级卡，跟着正文流式长出 |
| 出现时机 | 本轮结束后才渲染，流式期看不到 | 正文写到哪长到哪；长开标签会先白屏 |
| 根元素 | 普通片段，没有 `#vcp-root` 要求 | 必须 `<div id="vcp-root" style="…">`，只认 id |
| 样式作用域 | iframe 内自成一界，不必加前缀 | 渲染层作用域化成 `#vcp-msg-N`，类选择器一律带 `#vcp-root` 前缀 |
| 脚本 | 默认执行；设置里「允许执行脚本」可关 | 默认不写 `<script>`：不可信模式会过滤；可信模式放行也不作为交付依赖 |
| 主题色 | 用 `--v-bg-base`、`--v-text`、`--v-brand` 等 `--v-*` 变量 | 用固定色板或 `data-vcp-preset`；`--v-*` 不是它的变量 |
| 交互 | 按钮、键盘、canvas 都能跑 | `<details>`、`onclick="input('…')"`；radio+label 实测点不动 |
| 尺寸 | 指 iframe **里面**你交的片段：宽度自适应、高度按内容，`height` 可选；iframe 外壳高度由宿主定（见前文「外壳由宿主决定」） | 根容器 `width:100%`，别写死 `max-width` |
| 失败症状 | 工具成功但用户看不到卡＝client 半没加载 | 根容器写错＝整段 HTML 被转义成源码 |

混用的后果，记住四条：

1. 在 `render_visual` 的 HTML 里写 `#vcp-root` 前缀的 CSS——全部失效，只剩裸文字。它不在 VCP 的作用域里。
2. 在 `render_visual` 里用 `#vcp-msg-N`、`data-vcp-preset`、DSH 正文变量——同样没有，别假设它们存在。
3. 在 VCP 正文里调 `render_visual` 补一张卡——两条通道各出各的卡，重复占屏；一条消息一张卡。
4. 把 `render_visual` 的窗口当正文——用户看到的是卡，不是你的判断；话仍要写在正文里。

**为什么是这几个**：本机比对过四个可视化插件——`dsh-visual-card` 1.0.0（23.7 KB、零 peer 依赖、无 engines 约束）、`dsh-visual-interactive-engine` 0.32.0、`dsh-manim-card` 0.2.0、`dsh-visual` 0.1.1；最终选定 `dsh-visual-card` 供 `render_visual`。它和 VCP 覆盖「静态卡 + 脚本卡」两类。2026-11-22 又装了第三个 `dsh-a2ui` 0.3.1 专管「数据型」，三条分工见下一节。

**别再叠第四个渲染器**：每多一个，我每次都要多判一次「这次该用哪个」——这个判断成本是真实的，比省下的几个 token 贵。再加渲染器之前先证明现有三个都做不了。

**插件装没装好，先分清两半**（2026-11-14 实测）：

- `dsh-visual-card` 的 host 半（`render_visual` 工具）装完热加载、立刻可用；client 半（iframe 渲染器）要重启宿主或重载页面才加载。
- 症状：工具回「已生成可视化」，用户那边没卡。这时不要改 HTML，先查 client 半。
- `package.json` 里 `dsh.client.platform=web` 就是要重启的信号；有这行就不能说「不用重启」。VCP 同样是 web client 插件，改完照此处理。

## 三个渲染器怎么选

先认清这是三个不同的东西，不是同一套规范的三种写法。选错通道的代价是整张卡白做。

| | **VCP 裸 HTML** | **`render_visual`** | **`a2ui`** |
|---|---|---|---|
| 我怎么给 | 正文里直接写裸 HTML | 调工具传 HTML | 调 `a2ui` 传声明式 JSON |
| 在哪渲染 | 主文档内，替换 assistant 渲染器 | 沙箱 iframe，卡在本轮回答下方 | 主文档内，26 个受控组件 |
| 脚本 | **不执行** | **真执行** | 不执行，也不需要 |
| 自由度 | 最高（任意 CSS/SVG） | 高 | 低（只能用组件） |
| 专长 | 装帧、叙事、排版、公式 | 真交互、小游戏、canvas | 数据型：表格排序、图表、进度、滑块、逐步播放 |
| 做不了 | 需要脚本的交互 | 跟正文长在一起 | 装帧（纹理、serif、SVG 封面）；不能跨轮改历史卡 |

**选路不在这里重复**——默认 VCP，三条升级（可比数据 → `a2ui` / 要真跑脚本 → `render_visual` / 要留成页面 → `personalized-pages`）与换形态（单文件）都在上文「判据」节，一处定论，避免三套判据互相打架。这里只留两条经验：`a2ui` 省掉的是我手写 SVG + 自己防对比度与流式抖动；只用它来装帧则是自找麻烦。

**别把 a2ui 当万能**：它做不了我们现在多数卡的装帧型（纸质纹理、serif、SVG 封面、长文版面）。数据一少（一个数字、一句结论）也不该用它——它自己的判据就写着「单个事实不生成界面」。

**a2ui 的四条硬约束**（读源码确认）：

- **默认主动**：`autoRender` 默认 `true`，数据型回答会自动出界面。不想要就在插件设置里关掉，或让它在「用户要求 / 明显需要」时才出。
- **组件受控**：只能从 26 个受控组件里选（18 基础 + 8 扩展），不是自由 HTML。
- **一次调用一张独立快照**：不支持跨轮改写历史卡片；要改就重新生成一张。
- **只有按钮能把消息发回会话**（以 `[A2UI action]` 开头），副作用仍走常规工具——界面不能给自己授权。

**施工入口（别凭记忆写 schema）**：先调 `a2ui_catalog` 拿组件与字段名——`BarChart`／`LineChart`／`PieChart` 要 `categories` + `series`，`Table` 要 `columns` + `rows`，指标用 `Stat`／`Row`，可拖参数用 `Slider` + `Plot`；根组件 id 必须是 `root`。只写「26 个受控组件」等于没给入口。

**a2ui 表达不了就回退 VCP**：误差棒、统计注释、双轴、自由 SVG 版面、装帧型图表——受控组件里没有对应物（不能往组件里塞自定义 SVG）。判据：**图要传达「数据形状之外」的信息**（置信区间、标注、自定义刻度）就走 VCP 手写 SVG，别硬掰 a2ui。

**三个都不合适的时候**：你要的如果是「以后还能打开、能反复用」的东西——一个面板、一个清单、一个随时点开看的小工具——三个渲染器都不对。那不是「这一条回答怎么呈现」的问题，是「要不要给它一个常驻位置」，走 `personalized-pages`（它只管提案流程，本身不是渲染器）。判据：这东西我明天还会打开吗？会 → 走出口；只看这一次 → 发一张卡。**但「跨设备／存档的文件」不走这个出口**——那是单文件 HTML（见「跨设备单文件」节）；出口只管「应用内能反复打开的页面或小工具」。

## 发卡前自检清单

按顺序过，每项都能当场判：

1. **渲染器可用**：`render_visual` 工具在不在？设置 → 可视化 → 「允许执行脚本」是不是开着？关着就只剩静态内容。
2. **脚本语法**（`render_visual` 专用）：把所有 `<script>` 内容抽出来，`try{new Function(src)}catch(e){}` 跑一遍。语法错时整段静默不执行——工具成功、卡片空白、SVG 各 `<g>` 全空。典型事故：`var AX={{a:[1,0,0]}}` 多套了一层花括号。
3. **根容器**：VCP 卡的第一行是 `<div id="vcp-root" …>`。写成 `class="vcp-root"` 无效；裸 `<div>` 会让整段被转义成源码。
4. **样式位置**：`<style>` 紧跟根容器开标签、内容之前；选择器全部 `#vcp-root` 前缀；根与设宽容器 `box-sizing:border-box`。
5. **字体声明**：每个 class 显式写 `font-family` 与 `color`，写进 `#vcp-root .x{}` 规则；子元素行内不写 `font-family`（会被兜底成黑体）。
6. **字号**：VCP 用 `var(--dsh-content-font-size, 14px)` / `var(--dsh-content-font-size-secondary, 13px)`，标题 `calc(... * 1.3 / 1.6)`；不确定的变量不要猜，改用 em 相对单位。**字号必须写进 `#vcp-root{}` 规则，不要写在根容器开标签的 style 里**——开标签字号会触发渲染层 ref 锁，把整条消息容器一起设成该字号，同一条消息里的正文被牵连（2026-11-18 实测：卡内正常、卡上正文异常放大）。
7. **对比度**：正文与关键标签 ≥ 4.5:1；深底次要文字不低于 `#9aa1aa`。强调靠字重、字号，不靠把字调淡。
8. **交互形态**：要真交互 → `render_visual`；VCP 只用 `<details>` / `<summary>` 或 `onclick="input('…')"`；radio+label 标签页换掉。
9. **宽度**：`width:100%`；不写死 `max-width`（560px 已被用户否过）。
10. **体量**：CSS ≤ 约 200 行、类选择器 ≤ 12；一屏一焦点，主标题最重，其余退后。
11. **流式安全**：vcp-root 内与 `<style>` 内无空行；无 `backdrop-filter`、无 `flex-wrap:wrap`、无 `margin:0 auto`；入场只用 opacity 淡入，不用位移与 `animation-delay`。
12. **窄屏预览**：按 468px 宽扫一眼，大标题有没有糊成一块、字有没有小到看不清。
13. **正文在前**：同一条消息里先写纯文本判断，再发卡 / 调工具（见最后一节）。
14. **单文件**（只在要存档时）：按「跨设备单文件」四步走，写完 `read` + `IndexOf` 双重校验标签平衡。

## 字体与对比度红线

这些是用户四次截图纠正出来的，不是审美偏好。风格文档的推荐与本节冲突时，以本节为准。

**大标题**

- 首选系统 `Microsoft YaHei` + `font-weight:700`，最稳。
- 或 `Lanxi-HeiTiBold` / `Lanxi-朗宋`。
- `Lanxi-超粗黑` 在深色底、大字号上**不要用**——白字笔画会粘连成一坨。
- 大标题不要用 `Lanxi-静黑超细`（21/23px 已糊成一片）；风格文档若推荐它，按红线改掉。

**正文与辅助字**

- 正文一律系统无衬线；艺术字只做标题，单卡最多 1-2 款。
- **萌系手写体一律进不了信息位**（`Lanxi-叮叮` / `喵喵` / `丫丫体` / `秀英体` / `初心少女` / `暗恋初夏` / `卡通` / `MaShanZheng`）：它们只服务手账、日记、贺卡这类**装饰场景**，一旦承载路径、参数、数字、脚注、元信息就是误用。2026-11-22 用户原话「这个字体禁用一下，好垃圾的字体，根本看不清字」——起因是我把 `Lanxi-叮叮` 当脚注的等宽字体用，字形结构不为阅读优化。**脚注与元信息用系统等宽**（`Consolas`/`ui-monospace`）或 `Lanxi-HeiTiLight`，别从「手写感」里挑。
- 极细/超细字体（`Lanxi-静黑超细`、`HeiTiLight`、`WenKaiLight`）只许做水印或英文点缀，**禁止承载信息**。
- 数字用 `tabular-nums`，中文用全角标点。

**颜色**

- 浅底次要文字 `#7096D1` 对比度约 3.4:1，不达标；改用 `#5C7099`（约 4.6:1）。
- 本机 porcelain 浅底（`#fbfaf7`）实测：`#8a8377` = 3.60:1（不达标）、`#a8a094` = 2.48:1（严重不足）；改用 `#6b655b`（5.53:1）与 `#5f5a52`（6.55:1）——2026-11-19 逐色算过。
- 深底次要文字不要低于 `#9aa1aa`。
- 全卡至多一处强调色，最多两处呼应；深色容器里不要留白块、亮块抢焦点。
- **改字色必须成对看「字色 + 底色」**：只盯着字改会把浅底的字调深、深底的字调浅，单看一个色值永远判不出对比度够不够。改完在同一张卡上截一块肉眼看，或按 WCAG 算一次（浅底 `#7096D1` 3.4:1 不达标、`#5C7099` 4.6:1）。
- **同一张卡换主题（深↔浅）时明度语义整体翻转**：浅底里「更浅＝更次要」，深底里「更浅＝更亮＝更突出」；照搬浅底的灰阶到深底，次要字会抢主标题。换主题是重排层级，不是把色值反相。

**字号跟随用户设置**

- VCP 卡写死 px 就不跟 DSH 字号设置走，还容易整体偏小（2026-11-17 用户又抓到一次）。
- 做法：正文 `var(--dsh-content-font-size, 14px)`，辅助 `var(--dsh-content-font-size-secondary, 13px)`，标题按 1.3 / 1.6 倍算；或整卡用 em，根容器不设 `font-size`，子元素写 `0.85em` / `1.7em`。 字号要有可数的阶梯：正文 `1em`、说明 `0.9em`、标签 `0.78em`、标题 `1.7em`；行高写无单位 `1.85`，间距与内边距也走 em（如 `padding: 1.9em 2em`）。用户会自己调界面字号，写死 px 等于替他定死。
- **一条消息 = 正文 + 卡 + 选项卡**（2026-11-19 用户定调：「你现在是怎么做的，按你正在做的来，目前你这里正文卡片加选项卡片做的最好」）：先写判断与依据（一两段话），卡前空一行再给裸 HTML 卡；要拍板就紧接着调 `ask_user_question`，不要让用户打字。三者同条不会抢字号——「卡内正常、卡上正文异常」的成因是根容器写死了 `font-size`，不写就不会触发。
- `render_visual` 是 iframe，别假设 DSH 正文变量能取到；用 em/rem 相对单位，正文不小于 14px。

## 跨设备单文件

触发条件只有一个：用户明确说「要发给别人 / 离线看 / 手机看 / 打印 / 存一份 / **跨设备**」。这六个词是同一条判据的六种说法（「交付纪律」第 10 条写的「存档 / 跨设备」也指它），别按字面拆成两套判据。否则不要写 `.html` 文件丢路径——默认交付是正文里的卡，不是文件。

**真要写文件时落在哪**：`<cwd>\<主题>.html`（工作区根目录，用户一眼能找到）。正文仍要写清「这是什么、怎么打开、关键内容是什么」，路径只是补充、不当交付；文件已落盘就在同一轮调一次 `present` 让用户能点开，别只贴路径。

四步配方（2026-09-15 交付「课程表-2026秋.html」验过）：

1. **样式全部内联**：单文件零外链，CSS 写进 `<style>`，不引任何外部样式表、脚本、字体。
2. **字体用系统字体栈**：`-apple-system` / `Segoe UI` / `PingFang SC` / `Microsoft YaHei`。**绝不能依赖 `Lanxi-*` 等 DSH 插件字体**——离开本机就回退，排版全塌。
3. **viewport + 媒体查询**：加 `<meta name="viewport" content="width=device-width, initial-scale=1">`；窄屏重排——横排表格改单列、横向周历条改整行。
4. **`@media print`**：让 Ctrl+P 出干净的纸，不把按钮、阴影、深底一起印上去。

交付前校验：

- 用 `read` 读回文件，再用 `IndexOf` 数一遍成对标签，确认没有未闭合 / 错嵌套；标签不平衡先修再交。
- 正文里给一句「这是什么、怎么打开、关键内容是什么」，不要把文件路径当交付。

## 交付纪律（卡片 ≠ 正文）

**一条消息的结构固定**：纯文本判断在前 → 卡 / 工具调用在后。不许只弹卡。

**弹卡会盖住正文**：`ask_user_question` 的选项卡浮在消息下方，卡片或正文一长，用户眼里就只剩选项。所以正文要短到一眼能看完，关键判断不能落在卡后的段落里；正文已说完结论，卡只承载结构。

为什么写成死规矩：截至 2026-11-17 已违规 12 次；217 次 `ask_user_question` 里 140 次同一条消息零正文。病根不是平台限制，是把「说」和「做」拆成了两轮。

具体执行：

1. 正文必须是**纯文本段落**：判断依据、取舍、结论。塞 HTML 卡不算正文；只把依据塞进 `question` 首句也不算（2026-11-17 已被用户否掉）。
2. 道歉句之后必须紧跟正文本身，不能又是一张卡。
3. 用户说「先看正文」时，这一轮只写正文、不弹卡。
4. 选项里引用的清单、编号、候选，必须先在本条正文完整呈现；正文不能只有「详见选项」。
5. **产物类请求直接交付产物**：要卡片就给卡片、要图就给图、要报告就写报告。不要先用 `ask_user_question` 探路——2026-11-14 连续 4 次只弹卡，用户回了 4 次「没正文」。
6. 卡里不重复正文整段：正文说判断，卡承载结构；两边各说各的，互补不互抄。
7. `render_visual` 的卡在本轮结束后才出现。流式期间说「下面有卡」用户看不到；要说明也等本轮收尾。
8. VCP 卡的正文与卡在同一条消息里，卡前空一行；卡不要替代你要说的话。
9. **`onclick="input('…')"` 是直接发送，不是复制**：点击会把文本填进输入框并发出去。可复制的长串（准心码、命令、配置、路径）一律给纯文本或代码块，绝不挂在 onclick 上。
10. 单文件 HTML 只在用户明确要「发给别人 / 离线 / 手机 / 打印 / 存一份 / 存档 / 跨设备」时写（与「跨设备单文件」节同一份清单）；正文仍要呈现核心内容，不能只说「文件已保存」。
11. DSH 正文里 Markdown 引用块（`>`）内的 `**加粗**` 不渲染，整段按平铺文字显示——给用户可复制的邮件／模板／清单时关键句改用【】标注或 HTML 高亮块；判据＝预览里加粗与正文同色同重。

**最后一道判据**：把卡删掉，正文还成立吗？不成立＝正文没写够。把正文删掉，卡还看得懂吗？看不懂＝卡没做清楚。两边都成立才发。

## 附录：路径约定（跨机器可用）

本技能里的 `C:\deepseek\...` 与 `C:\Users\ZQY\...` 是作者机器上的实例路径；方法判据与下表配合，换台机器照样能跑：

| 符号 | 含义 | 作者机器实例 | 通用写法 |
|---|---|---|---|
| `DSH_HOME` | DSH 数据根 | `C:\Users\ZQY\.dsh` | `%USERPROFILE%\.dsh`（或环境变量 `DSH_HOME`） |
| `PROFILE_DIR` | 当前 profile | `DSH_HOME\profiles\desktop` | `DSH_HOME\profiles\<profile 名>` |
| `SKILLS_DIR` | 用户技能目录 | `C:\Users\ZQY\.agents\skills` | `%USERPROFILE%\.agents\skills` |
| `NODE_BIN` | Node 可执行 | `DSH_HOME\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe` | DSH 自带运行时，或 PATH 里的 `node` |
| `TOOLS_DIR` | 自建工具目录 | `C:\deepseek\tools` | 任选，固定后写回本表 |
| `PLUGINS_DIR` | 插件归档目录 | `C:\deepseek\插件` | 任选 |
| `WORK_DIR` | 工作区 | `C:\deepseek\work` | 任选 |
| `STUDY_DIR` | 学习资料 | `C:\deepseek\study` | 任选 |

换机器三步：①确认 `DSH_HOME`、`SKILLS_DIR`、`NODE_BIN`；②`scripts/` 里的常量在文件顶部，改成新路径再跑；③其余判据（版本号、报错串、行号、端口规则）与具体路径无关，通常不用改。
