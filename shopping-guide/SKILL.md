# 挑商品（shopping-guide）

用户定调的方法：**先了解原理 → 再看商品用途 → 探寻买点与差异点 → 结合需求分价位提供建议**。跳步就会变成「报型号 + 报价格」的敷衍答案。

## 总流程（前置 + 四个步骤，顺序不可跳）

### 0. 先确定现状（不可跳）

开挑之前先确认**使用者的现状**，写成一段画像。只有能改变型号选择的三项必须问到，其余的边给候选边补：

1. **预算区间**——含「最多能到多少」；不说就先按三档给，别停住等；
2. **硬约束**——尺寸 / 接口 / 系统生态 / 不能接受的东西（不能入耳、不能打孔、必须能退）；
3. **已有物品**——手上有什么、这次缺哪一件、是否接受先买一件再补。

其余字段按品类取：

- **地域/气候**：常驻城市、当季温度区间、室内有没有空调暖气、湿度/雨季、通勤是否淋雨；
- **身体**：身高、体重、关键围度（腰/臀/大腿/脚长等），有无尺码踩坑史；
- **场景**：通勤方式与时长、久坐还是久站、使用频率、和什么搭配、洗晒条件；
- **预算与口味**：价格带、版型偏好、颜色禁忌、品牌偏好、能不能接受改衣/退换；
- **不确定项**：逐条列出来，逐个问用户（用 `ask_user_question`）或按最保守假设处理并在结论里注明；
- **品牌黑名单**：先问「哪些牌子一律不要」，用户说过的直接前置过滤。**本线用户偏好（2026-11-10 起）：联想/Lenovo 全系及其子品牌一律不推荐**——含 ThinkPad、Legion 拯救者、小新、YOGA、Motorola；电子产品尤其严格，候选里不出现，也不拿它做对比基准。换用户先问，别把这条当普适规则。

数码取「已有设备与接口 / 系统与生态 / 主要用途 / 桌面还是携带」，家居取「房间尺寸与摆放位置 / 门宽与电梯 / 能不能打孔」，耗材取「用量与频次 / 存放条件」。

现状没确认就开挑＝大概率挑错（2026-11-09 用户要求：先完整判断现状与需求）。

**但「必问」不等于「全问」**：喜好、颜色、品牌缺了就按最保守假设先给候选，边给边问，不要为了追问而停住不动（与第 2 步一致）。现状定完进入「调研纪律」——顺序与判据都在那一节，不在这里重复。

### 1. 先搞懂原理

在报价之前，先讲清这个品类**是怎么工作的、什么变量真正决定体验**。

- 找出 3–6 个物理/技术变量：例如耳机＝密封方式（半入耳/入耳）× 无线链路（蓝牙/2.4G）× 单元尺寸 × 麦克风阵列；扫地机＝吸力 × 滚刷形态 × 导航方式 × 基站能力。
- 讲清变量的**代价关系**，不只讲好处：半入耳＝不闷但低频与隔音天然弱；2.4G＝低延迟但占一个口、要接收器；大电池＝重。用户要能听懂「为什么便宜的那款注定差在哪」。
- 原理没搞清就先别报价；宁可先说「这个品类我先确认一下」。

### 2. 再看用途

把「品类」拆成「场景」，同一品类不同形态服务不同人。

- 问清（或从上下文推断）：**在哪用**（电脑/手机/通勤/运动/会议）、**用多久**（一局一小时 / 整天挂）、**和什么设备配**、**有没有硬约束**（戴眼镜、耳道敏感、不能入耳、必须能退）。
- 明确说出「哪些形态不适合你的场景」，比列一堆型号更有用。
- 用户没给场景时，先按最常见的 2–3 种场景各给一条判断，再让他选；不要为了追问而停住不动。

### 3. 探寻买点与差异点

把「厂商买点」和「真实差异」分开，这一步是选品质量的分水岭。

- 厂商买点常见噪音：灯效、联名、堆词（「AI 降噪」「电竞级」）、像素级参数、赠品。
- 真实差异通常只有 3–5 个，且往往带代价：延迟、续航、佩戴、麦克风、生态/App、售后。
- 对每个候选，找出**一条可验证的负面证据**（差评、论坛吐槽、测评里的但是）。
- 判据：如果两个型号的差异只体现在宣传语里，就告诉用户「这两款实际是同一档，按价格和售后选」。

- **不找「没短板」的机子**：让用户选「能接受哪个缺陷」，每个候选给 2–3 条线下验机项，比看评分有用。
- **参数自己换算成物理量再采信**：100W＝20V×5A，线必须 5A E-Marker（3A 线只到 60W）；多口同插会分功率、单口才满血；PD3.1 140W 要 28V 档，设备只到 20V/5A 时无效；品牌私有 140W（如机械革命）只能原厂头触发。换算不出来就写「未验证」。
- **读「分档/刀法」类内容逐条对齐主语**：每句话先问「说的是哪一档、哪个型号」，别顺读串行，把低档的评价安到高档上。

### 4. 结合需求分价位建议

- 按预算分 3–4 档（例如 200 / 400 / 800 / 1200+），每档 1–2 款。
- 每款写：**为什么是它**（对应哪条需求）+ **代价是什么**（续航/音质/缺货/生态）+ **怎么退**（有风险时）。
- 最后必须收口：一个明确首选 + 一句「什么情况下别买这款」。
- 价格跨度大时，说明「多花的钱买到了什么」，别只报价格差。
- **同一轮只给：一句判断 + 2–3 个候选 + 一张选项卡**；下一轮按答卷收窄，不要一次铺十款把用户淹掉。

- **排序按缺陷接受度，不按评分**：续航 4h、底噪投诉、自营缺货比「几分」更能决定买不买。
- **每档附验机清单**：到货先验哪三项、什么情况直接退，写在该档建议后面。

## 调研纪律

### 顺序：先 B 站铺候选，再回京东核价

B 站解决「这类东西该怎么挑、哪些款被反复提到、哪些坑是通病」；京东解决「此刻到手价多少、我要的尺码有没有货」。**顺序反了就会拿关键词乱搜，搜出来的是改标题的杂牌。**

- **多看几个**：同一品类至少 5–8 个视频再收口，只读 1–2 个容易被单个 UP 主的偏好带偏。
- **筛广告的判据**：一口气推 10 款以上、评论区或简介挂购买链接、话术只剩形容词（「闭眼入」「不买后悔」「三天不吃饭都得入手」）、通篇没有实测过程——这类**只留方法论，不留型号**。实测类视频的典型特征是给条件、给数字、给对比（「站 10 分钟温差不到 2℃」「300–400 g/m²」）。
- **通道**：口播与画面走 `bili-transcript`（口播用 `bili_summary` 或 `transcript.mjs`；简介/评论用 `client.mjs` 调 `bilibili_video_info` / `bilibili_video_comments`），要核对页面时配合 `browser-skill`。
- **单件商品给 2–3 个推荐**（2026-11-25 用户要求），不要只报一个型号就收口。

### 样本与来源

样本不足会直接导致选错（2026-11 曾因样本不足被连续纠正三次）。型号要覆盖全，视频的**正文、简介、评论区**都要读，评论区只是旁证不是结论。先把候选铺满，再收口。

候选来源按优先级：

1. B站实测视频（口播 + **评论区**，评论往往比视频诚实）；
2. 论坛真实用户（NGA / ZOL 点评 / 贴吧 / 知乎回答）；
3. 导购站（什么值得买）交叉验证价格与历史价；
4. 京东/淘宝**登录态**页面拿实时价（`browser-skill`）。

**品类带宽**：先量「真正满足硬条件的有几款」。只有 3–5 款时如实说「就这么多」，向相邻形态扩列并**明确标注形态不同**（入耳式、开放式耳挂各列一组，写清「不是你要的形态」）；绝不用关键词堆砌的杂牌凑数。

**发布信息按机型逐个搜**：搜「机型名 + 发布/开售/价格」，比年度盘点准；百度百科正文容易被导航淹没，ZOL 有防刷验证页，别把抓到的首页当参数页。

### 证据分层

写结论时标清四层：官方标称 / 评测口径（含测试条件）/ 买家实测（带 rpid、评论楼层等可回溯门牌）/ 论坛个体反馈（标明是普遍问题还是个体风险）。每条负面都要能指回具体的人或帖，**指不回去的算没查到**。

官方与买家数据冲突时以多例买家为准，并**把冲突写出来**，不要只报一边。**负面证据必须写**：赌的是什么、概率多大、怎么退。只讲优点的推荐等于没做。

### 价格可信度：四关

报价必须走完**「登录态 → 自营有货 → 到手价折算 → 交叉验证」**四关，缺一关就不报成交价，只能标「未核价（缺第 N 关）」。

1. **登录态**：京东/淘宝的价格与库存只认**登录态**；未登录看到的是未登录价/推荐价。
2. **自营有货**：先确认自营或官方旗舰店有没有货。第三方加价、缺货抬价都不能当比较基准；同一商品不同第三方店铺价差可达 200 元。
3. **到手价折算**：预售页读**定金 + 尾款**，别把页面价当成交价；页面价要区分**券前 / 券后 / Plus 价 / 百亿补贴**。导购站公开可读，只用来**交叉验证**历史价与口碑，不当成交价。
4. **交叉验证**：至少两个来源对上（商品页 + 导购站/历史价/评价），对不上就把差异写出来。

平台已失效的通道：京东价格/评价 **API 都不可用**，只能读登录态页面 DOM；价格类 MCP 也已全部不可用（best-price-mcp / cn-ecommerce-mcp 已删）。2026-10-22 起**唯一可靠的在售价来源是 `browser-skill` 读登录态 Chrome**。

### 平台操作与风控

- **页间隔 6–10 秒**，别一个接一个开；一次只走一条浏览路径，不快速 reload、不反复后退。
- **不要开未登录窗口**——没有正常 cookie、没有登录态，反而更容易被拦。
- **触发风控立刻停手**：验证页 / PC 频控页 / 搜索页静默降级都算；停 30–60 秒起步，频控页隔十几分钟，连续重试只会越拦越紧。
- **取图优先走搜索页结果卡**：一次搜索页能顶掉 2–4 个商品页的请求，是最省的取图方式。
- 验证页 URL、DOM 选择器、取图细节、会话回收报错、具体机型案例，见 `references/jd-pages.md`——这些是实现细节，不占正文的判据位。

## 停止条件

- **候选够了**：同一品类 5–8 个视频，且连续两个视频不再出现新候选 → 停止扩列，进入核价。
- **核价够了**：四关走完 2–3 款 → 出方案；其余候选标「未核价」，不硬凑。
- **搜不动了**：连续两次搜索没有新候选，或已触发风控 → 停，用已有证据出方案并写明覆盖不足。
- **问不动了**：同一个问题问两次仍无答案 → 按最保守假设出方案，缺的那项标「待确认」，不再追问。
- **用户催了**：先给最小可决策方案（1 主推 + 1 备选 + 还缺什么），不为了凑满三档而编。

## 交付形态

- **给建议前先讲原理与挑选要点**：每次给候选或报价前，先用 3–5 句说清「这类东西靠什么起作用、哪几个变量决定体验、你的场景该优先看什么」，再放图和价（2026-11-09 用户要求）。
- 多个可选方案时，用 `ask_user_question` 弹选项卡（≤5 项、每项一句代价、推荐置顶），**正文不要重复罗列选项**。
- **先给实物图，要大、要能看清关键细节**，图按品类的关键变量选：

| 品类 | 配什么图 | 看什么 |
|---|---|---|
| 服装 | 真人全身实拍 | 版型、垂感、裤长、收口 |
| 数码 | 屏幕点亮实拍 / 接口特写 / 整机正面 | 屏幕素质、接口位置、做工 |
| 家居 | 放进房间的实景 | 比例、占地、风格 |
| 耗材 | 包装与规格贴纸 | 型号、容量、真伪标识 |

- **每个候选都要配图，不许因为卡片变长就省图**（2026-11-25 用户要求，卡片长就长，宁可长不可缺图）——同一商品的 2–3 个候选、每一档的每一款都要有自己的图；确实拿不到才退回「产品图 + 链接」并写明「无实拍图」。
- 每条配可点商品链接，让用户自己看版型/颜色。
- 报告结构建议：一句结论 → 对比表（型号/到手价/关键参数/一句话）→ 逐款细节（长文用 `<details>` 折叠，别用渲染层点不动的 CSS 单选 tabs，见 `html-card`）→ 口径与下一步。
- 文字优先，视觉卡只在需要对比或氛围时用；卡片内不用 Emoji。

## 边界

- **只接「要挑」的活**：已购商品的**售后、保修、故障排查、维修**不接——说清边界，转品牌官方售后/保修入口；要排查具体故障就另开流程，别混进选型。
- **纯参数查询**不接：直接答参数即可，不进挑选流程；要对比或要推荐才走本技能。
- **价格监控**不接：没有持续盯价的能力；用户要一次性核价，按「四关」做一遍并注明查价时间。
- **不含挑选动作的购物清单**不接：照单整理或执行，不替换型号、不夹带推荐。
- **不代下单、不代付款、不填支付信息**：给型号与链接，由用户自己下单。
- **黑名单照第 0 节执行**；换用户先问，不把本线偏好当普适规则。**商品事实不写进记忆库**：型号、价格、配置对比都不落库；黑名单属于用户偏好、不是商品事实，可以记。
- 不做医疗/健康类功效断言；涉及安全（电池、承重、儿童用品）时把风险写清。
- 拿不准的参数写「未标/待确认」，不要编。

## 干完怎么算对（验收）

- [ ] 用户拿到了**能直接做决定的东西**：2–3 个候选 + 各自关键差异 + 对应价位，不是参数罗列。
- [ ] 每个候选都有一张能看清关键细节的图（或写明「无实拍图」）。
- [ ] 每个候选都有走完四关的到手价（或标「未核价」并写明缺哪关）。
- [ ] 每个候选至少一条**可回溯的负面证据**（指不回具体人或帖＝没查到）。
- [ ] 每个候选 2–3 条验机项，加一句「什么情况下别买」。
- [ ] 首推另有一句「它的代价是什么」。
- [ ] 每个「更好」都说了**好在哪个具体场景**，没有笼统的「性价比高」。
- [ ] 用户还在犹豫时，先判断是不是**缺证据**（负面证据/价位没铺到）——缺就补，不是继续堆参数或加选项。
