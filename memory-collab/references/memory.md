# 记忆与准则维护

> 场景：写一条记忆、整一批记忆、给库体检、改准则文件、搬记忆目录。
> **作用域（唯一口径）**：默认只写当前工作区库；只有「换个工作区打开还成立」的本机知识才写全局库（§4）。带日期的实测在 `evidence/measurements.md`，本文只留判据。

## 1. 库位置与状态

- **工作区库** `<cwd>\.dsh-mind\memory.db`（配置项 `projectDir`，默认相对 cwd；旧 `.dsh-meow` 只作回滚保留，别再写）。
- **全局库** `<globalDir>\memory.db`（配置项 `globalDir`，本机默认 `GLOBAL_DIR`；设空串＝关闭全局库，信箱一并停用）。`project` 填「全局」即落这边，其余工具按 id 自动定位。
- **看现状用 `memory_home`**：只读，返回两条路径 + 各层条数；**不带参数、不做迁移**（旧写法「带 target 迁移 / 热切换」是旧版行为，0.1.2 没有）。
- **表**：九层 `soul`/`user`/`project`/`fact`/`lesson`/`principle`/`topic`/`rules`/`todo`；时间线 `episodes`/`phases`/`decisions`/`personas`/`persona_traits`；旁挂 `events`（原始档）/`memory_vectors`/`memory_evidence`/`memory_relations`/`memory_versions`/`memory_feedback`。**没有 `memories` 表**；表清单随插件版本变，别信手写，读 `sqlite_master`。
- 版本流水不进记忆层：用 `memory_log` 的 add/list/remove/stats 或 `/log`；记忆只留当前基线与选型判据。查数用只读打开 `select status, count(*), sum(length(content)) from <层> group by status`。
- **status 六态**：`observation`/`evidence`/`candidate`/`memory`/`review`/`evolution`。新建默认 `memory`；检索与注入只认 `memory` 与 `evolution`（`evolution` 计划退役，别写）；`review` 按 id 可回读、不进检索。旧三态：`active`→`memory`，`stale`／`archived`→`review`。

## 2. 判据：先分四类

| 触发 | 类型 | 动什么 | 汇报 |
|---|---|---|---|
| 新事实或教训；用户说「记住」；出现「以后…都…」 | 写一条 | 新增或 update 一条 | 当轮一句 |
| dream、合并重复、拆超长、批量归档、插件改名后扫旧名 | 改一批 | 多条，串行 | 收尾给回执 |
| 「体检」「自检记忆库」「清理过时条目」 | 体检 | 全库四类问题，当场修完 | 报告带前后数字 |
| 搬记忆目录、改 `globalDir`、换盘 | 迁移 | 库目录与配置 | 动手前说清代价 |

三条总纲：

1. **授权边界**：用户已授权「体检 + 清理 + 拆分」属常规维护（2026-09-30 原话「你觉得怎么改好就怎么改，不用一直问我」）——**但只管「改」**：改状态、降 `review`、补关键词、拆条、重建索引这类可逆动作不必逐项征询；**永久删除与归档仍逐条先问**，一句话说清删什么留什么。例外：用户已明说「归档这条」「删掉它」——直接做、事后报一句。删或改用户本人的事实信息同样谨慎，拿不准标「待确认」。
2. **写入串行**：同一批不要并行发 `memory_remember` / `memory_update`——并行可能返回同一 id 静默丢内容，或生成重复条目。
3. **只动自己的库**：跨工作区、共享面（`memory_mail` 信箱、共享脚本、别人的库）的改动，当轮 `memory_mail post` 留痕。

说不清属于哪一类就先只读不写。**体检当场修完**，不许只报问题。**「长期用不上」看 `last_accessed_at`，不看 `hit_count`**；误命中不算有用。**压缩摘要时行内代码只脱反引号、保留内容**（里面常是文件名/工具名/配置键，剥掉就没主语；代码块可整删）。

### 长度：一张表，不许有第二套

| 层 | 硬上限（按 `content` 字数） | 理由 |
|---|---|---|
| `fact` | 60 | 一句一件事 |
| `rules` / `lesson` | 250 | 要带判据、边界与数值，砍到 200 会变成空口号 |
| `topic` | 300 | 前因后果需要篇幅 |
| 其余（`soul`/`user`/`project`/`principle`/`todo`） | 200 | 多是单一结论 |

- `title` 自动取 content 首句前 40 字，属派生字段，**不计入上限**（按 title+content 算等于把上限压到 160，会误判一堆合格条目）。
- **压缩触发器＝硬上限的 80%**（`fact` >48、`rules`/`lesson` >200、`topic` >240、其余 >160）就先压；**触发器必须低于硬上限**，写反了永不触发。压的时候砍现场叙述，留报错串、路径、判据、指针；超限先拆成两件事，真拆不动再删细节。
- **时间线（`episodes`/`phases`/`decisions`/`persona_traits`）不设字数上限**：九层要挤进首轮块与检索排名，时间线按 persona 隔离、注入只占「当前处境」一行。写经历**先写全**，压缩发生在注入渲染时。

## 3. 写一条：从判值到回读

0. **值不值得写**：下次还会用到、或这次踩过坑 → 写；一次性过程细节、能现查的文件内容、商品事实 → 不写。判据：这条被注入时，除了「哦」还能带来动作吗。
1. **先查重**：`memory_search` 用关键词或句子查同义条目；涉及某个项目先 `memory_project('<项目名>')` 拿全景。能 update 合并就不新增。
2. **判该进技能还是记忆**：技能＝操作手册（遇到 X 按 1-2-3 做），记忆＝证据与教训（那次为什么失败）。有步骤且反复用 → 技能；事实、坑、一次性教训 → 记忆；又流程又教训 → 技能写「怎么做」，记忆留「为什么」，只留一行指针。
3. **确认 project 与字段**：先看已有项目名，别把项目信息错标「全局」，跨多项目用英文逗号分隔；content 先写全再压到该层上限（§2）；keywords 取 8-13 个、按「用户会在什么话里提到它」反向拟，不用项目名当关键词；importance 四档＝4 致命红线／3 用户强调全局适用／2 用户决策或跨文件抽象／1 琐碎原子。
4. **串行写并回读**：一次只发一条；写完 `memory_read` 读回全文，确认 id、层、内容都对得上。跨会话约定尤其要回读——光在对话里说等于没发生。
5. **会话码不用手打**：`memory_remember` / `memory_observe` / `memory_update` 会自动从 `exec.agent.session.header.id` 算码补在正文末尾，已带码不重复。**别给别人的条目补码**——跨会话条目事后补本会话码＝假留痕；只有真由本会话产生才带码，`source_session` 同理。新会话不继承旧码，要沿用先问用户。
6. **长期约定立刻落库**：出现「以后…都…」「下次你说 X 我就 Y」，当场写 `rules` 或 `user`。
7. **动共享面当轮留痕**：归档、删除、批量改库、改共享脚本或配置，都在当轮回信里写清改了哪些、影响面、回滚方式；留痕写自己那份，别改别人的文件。

**证据必填**：原话、实测数字、报错原文写进 `evidence` 参数（`memory_update` 改正文时旧正文自动进 `memory_evidence`）。写 `fact`/`lesson` 时不能空；答不出就先别写事实类，改 `memory_observe`（观察不进检索，可以模糊）。**证据不全就挂起**：出处只到「大概」或证据互相冲突 → `status='review'` 并写清缺什么；判据是「三个月后有人问依据是什么，能直接读出出处」。**原话与数字照抄不要转述**——转述成更顺的句子就是「把原文没写的塞回去」的开始。补上证据后用 `memory_update` 带回 `evidence` 并把 `status` 改回 `memory`，它才回到检索面。

## 4. 两库判据

判据一句话：**换一个工作区打开，这条还对吗？** 对 → 全局；只对某项目、某段时间成立 → 工作区。

- 路由看 `project` 列不看目录；其余工具按 id 自动定位，不必自己选库。`memory_observe` 永远写工作区。
- **不许同一事实两边各写一份**；项目状态也不许挂「全局」骗路由；关系不能跨库（跨库建边会被拒）。
- 读不用管库：`memory_search` / `memory_read` / `memory_context` 自动两库，全局命中带 `[全局]`。回滚＝`globalDir` 设空串退回单库。

## 5. 写什么层

| 层 | 放什么 | 形态 | 判据 |
|---|---|---|---|
| `soul` | 只认**全局库**那条（跨工作区人格底色）；工作区 soul 段不再注入，本会话人格由 `persona_traits` 提供 | 少用 | 本会话专属的写 persona |
| `user` | 用户基本信息、基础偏好、设备与网络环境、关于本人的重要事 | 每会话注入，必须短 | 太长会挤掉真正重要的条目 |
| `rules` | 设计原则与行为准则；全局准则 `project` 填「全局」 | 一条一个准则 | 会被反复违反的才立 |
| `fact` | 细碎原子事实 | 一句话直陈，≤60 字 | 一条只装一件事 |
| `lesson` | 学到的经验、被纠正的教训 | 一句话，标 `corrected` | 被纠正过的一定记 |
| `principle` | 从多个事件里沉淀出的通用准则 | 短，一条一句 | 反复验证过才立 |
| `topic` | 一件事的前因后果与脉络 | ≤300 字，可更新 | 有过程、需全局视野 |
| `project` | 项目元信息 | 六个子类 | 只属于某一个项目 |
| `todo` | 即将要做的任务 | 完成后标 `review` 即 done | 有明确下一步动作 |

**persona_traits 不在这张表里**（按 persona 隔离，不参与九层检索），三条判据：①换个用途的会话还成立吗？成立 → 不是 trait（进 `rules`/`AGENTS.md`）；②它说的是哪种事？「他这个人」→ `user_profile`；「我该怎么做」→ `rules`/`AGENTS.md`；「在这个用途里我们怎么配合」→ trait；③一条只讲一个特质，写成「他/我 习惯…」。

**project 六子类**：`overview`（目的、总览）／`structure`（架构、目录、模块）／`decisions`（决策与理由）／`quotes`（值得留的用户原话）／`ops`（端口、路径、启动方式、库位置——断言「某处是什么」，要在 evidence 写清实测方式）／`todo`（即将要做）。**拆分与画像**：读一遍能用一句话概括就是一条，「另外」「还有」「顺便」多为混装，拆前先归档原文；`user` 与 `user_profile` 只收跨场景稳定的特质（价值观、沟通风格、交付偏好），只在某个场景成立的倾向归对应技能与准则层——判据是换一个场景还用得上吗。

## 6. 什么时候写时间线（事件 / 阶段 / 决定 / 性状）

时间线存「那段经历」，九层存「结论」。**没有自动入口**——`agent/pre-step` 只把用户原话捕获进 `events`（原始档，不进检索与注入），事件与阶段必须显式调工具。

| 写什么 | 判据 | 不写 |
|---|---|---|
| 事件 `memory_episode { op:'create' }` | 跨多轮、有明确目标（**不要求「持续数周」**——旧标准让时间线两库 0 条）；事后能回答「那阵子在忙什么」 | 单轮收尾的一次性任务（装插件、修 bug）——那是 `lesson`/`fact` |
| 阶段 `{ op:'phase_start', episode_id, env }` | 同一事件里**判断标准变了**（预算、时间、住哪、方向改没改） | 只是进度推进——开会自动归档旧阶段，为记进度反复开会把真实阶段切碎 |
| 决定 `memory_decision` | 有取舍（选 A 没选 B）且以后按它办事 | 单方结论、没有放弃项的选型 |
| 性状 `memory_persona { op:'trait' }` | 换用途不成立、但在这个用途里反复出现的配合方式 | 换别的会话照样成立 → `rules`/`AGENTS.md` |

- **工具自己会做的别手工补**：`phase_start` 归档上一阶段、`seq` 自增、写 FTS；`decision` 不给 `phase_id` 就挂最新阶段；`supersedes` 把旧决定降 `review`；`close` 归档其全部阶段。**`env`（场景标签）**：逗号分隔（`租房,预算紧,时间充裕`），同一事件内**复用同一套词**——换说法等于换维度，`memory_search { tags }` 就匹配不上；它也是首轮块「当前处境」那一行。
- **读**：`memory_search { event }` 收一个事件的阶段与决定；`tags` 只过滤时间线条目、九层照常返回，只想看场景就同时限定 `level:'phase'`。首轮块那行空着＝没建事件，接手长期任务先查现成事件，别重复建。

## 7. 删、合并、拆分、去重、批改

**先定位到具体条目**：用户说「这条」时别按标题猜 id——`memory_search` 找候选、`memory_read` 确认层与正文；定位不到就弹卡问。

### 什么时候删

1. **归档判据是「有没有后继事实」，不是「内容旧不旧」**：被取代的版本、被新结论改写的旧结论、重复条目 → 归档；「放了很久没用上」不等于过时（判据见第 3 条）。用户说「它过时了」先确认「被什么更新了」。**改了结论就当场归档旧条**——两条说的是相反的话，检索时都命中、模型各读一半，比同义重复更难发现。
2. **三种动作不要混**：归档＝`status` 改 `review`（退出检索与注入，按 id 仍可回溯；旧文档的 archived 就是这个）；完结＝`todo`/`topic` 标 `review` 并写清为什么；合并＝保留最新结论那条，其余归档。
3. **「长期用不上」三个证据一起看**：建龄 ≥ 1 个月、`hit_count` 为 0 或 `last_accessed_at` 久远、无后继引用（技能/准则/其他条目都不指向它）。建龄不满一个月且 h=0 不算证据。
4. **拆分先归档原文再写新条目**（反了会被自动合并回去）；**同日多批 dream** 动手前先查「本轮已经改过哪些条目」。
5. **插件改名或合并后扫全库旧名**：旧包名、旧工具名、旧路径；扫法＝逐层 `content like '%旧名%'` 数条数，再逐条 `memory_read` 判改还是删。
6. **先问用户**：删或改用户本人的事实信息；拿不准的条目（标「待确认」）；跨工作区或共享面的批量删改（先留痕再动）。**不可逆操作先留底**（db 备份或 `handover\` 存档）；单条归档不算——只改 `status`，随时能回读。
7. **禁止**：直插别人的 SQLite 库；用文件工具改库本体（读可以，写必须走 `memory_*`）；把归档当删除。

### 合并五步

选主条目（最新结论、信息最全）→ 被并条的独有事实补进主条（别只删）→ 被并条改 `review`、主条回读 → 关键词取并集再删冗余 → 在共享面就当轮留痕。

### 按技能去重（2026-11-21 用户口径）

用户原话：「先按技能去重，把技能覆盖到的记忆删掉」。技能是执行面、记忆是结论面，同一条判据两处都有就是两套真相。

1. **判据**：这条的核心判据或步骤，能不能在技能原文里读到？能读到且记忆没有额外信息 → 删记忆、留技能。**必须读技能原文**，关键词召回或「同主题段落」不算覆盖。
2. **三档**：`覆盖`＝技能已写明且记忆无新增；`部分`＝技能提到同主题但缺关键数字、报错串或边界；`零命中`。只有「覆盖」才删，「部分」先补技能再谈删。
3. **先补技能、再删记忆**：把阈值、报错原文、反直觉行为插进对应小节、改完 `node --check`／抽读确认，再删；删前存档（`handover\` 或 `memory_evidence`）、单事务删记忆 + 标记 + 证据。反着做，中途中断就丢内容。
4. **规模大切片派子代理**：按 `i % 4` 分片，每片只读子代理只写自己的 JSON（`{n, covered, where, quote, reason}`），主线合并后**自己抽查 3–5 条边界**——打开技能文件对应行核对原文，别信回执。**反例**：只看关键词命中就判覆盖，会把「提到同名词」误删（如「cron 表达式」误判成「定时任务技能已覆盖」）。

### 批量精修正文（用户批准全量重写时才做）

机械瘦身会留下「SKILL.md（69 行 / 5,815 B。」这类截断，自动 pass 修不好。

1. 备份 db（含 `-wal`/`-shm`），按层导出活跃条目为 JSON 分片（rules / project / topic / fact a-b / lesson a-c），一片一个子代理。
2. 任务书写死：正文＝结论＋判据、目标 80–160 字、**硬上限按 §2 长度表**、阈值/路径/命令/字段名逐字保留、删实测过程、修补残句与未闭合括号、单行无 Markdown、原会话码保留不新增。
3. **数据库由主线串行写**（多进程写同一个 SQLite 会抢锁）；**字数主线复核**——子代理自报的字数普遍偏小（实测自报 198、实际 206–293），用 `[...str].length` 过一遍。
4. 写入：旧正文先 `addNoteEvidence`（按 `memory_id`+`quote` 去重）→ `UPDATE` 正文 → 重建 FTS（§9），证据表顺带成了回滚来源。**验收**：超上限 0 条、占位符 0、各层字数与均值、抽读 5 条（含一条「数字过时」的，看是否已降级为判据）。

### 用户批改后的处置

1. 标记在 `memory_marks`（按 `verdict` 统计），**不是 status**。
2. **先对 `status`**：`memory_marks` 只增不减，用户连着批改两次时旧标记仍在——已是 `review` 的跳过，报告单列「早前已删 N 条」。不做这步会白跑一轮。
3. 评语三类：①「技能里已有」→ 核对技能原文，有就删；②「可以放准则里」→ 先写进 `AGENTS.md` 或全局 `rules` 再删；③「过时／环境信息」→ 直接删。标「有用」的一律保留。删前备份 db；**单事务**删记忆 + 标记 + 证据 + 向量 + FTS；未批改的不动，汇报写条数。

## 8. 体检流程

1. **先 `memory_health` 拿两库合计，再直读 SQLite 逐层看**（这两个工具都已按两库统计；只读工作区会漏全局那一批）。先导出紧凑清单（id、level、字数、摘要），再判问题。
2. **注意列差异**：九层都有 `project` 列；`lesson` 多一个 `corrected`（13 列 vs 12 列），别拿一套 `SELECT` 套九张表。
3. **四类问题逐个筛**：错误（与现状冲突）／重复（同一结论多份）／已完结（`todo` 完成、`topic` 达成 → `review`）／超长（一条装多件事 → 拆，先归档原文）。另加三类易漏：易腐快照（「已装 N 个」「库内 N 条」「现状（某日期）」）、无后继的旧版本结论、证据缺失（`fact`/`lesson` 与 `ops`/`structure` 的 `memory_evidence` 为空或只写「大概」——补出处，补不上降 `review`）。
4. **`rules` 层过时更隐蔽**：用户后来的口头澄清往往只写进 `fact`，`rules` 还停在旧说法，而 `rules` 每轮注入——错的那条更容易被读到。逐条问「用户后来改口了吗」，改口的并进 `rules` 正文、再把 `fact` 归档。
5. **「长期用不上」按 §7 第 3 条算**，别只看 h=0。**写操作串行，update 核对完整 id**：短前缀会撞（`0mvce0ck` vs `0mvce0cky`）；报「未找到该 id」但条目明明在时先看码位——`0`/`o`、`1`/`l`/`I` 在多数字体里分不清，用 `repr` 或 `[hex(ord(c)) for c in id]` 逐字符核（踩过：第 7 位是字母 `o` 不是数字 `0`）。
6. **收尾三件事**：回读校验；复算规模（活跃条数、总字数、归档条数）并带采集日期；一句回执（例：`2026-11-18 体检：405→370 active，147.1K→127.1K 字，归档 35 条`）。需裁决的单独列。**哨兵**：确认注入横条可见、`memory_search` 能返回结果；坏了当场说。**有跨工作区或共享面改动的**，按 §3 第 7 步留痕，再给报告。

**记忆验收**：写/改 → ①`memory_search` 能用关键词召回且内容正确；②keywords 8–13、project 对；③重复的先合并；④`fact`/`lesson` 与 `ops`/`structure` 的 `evidence` 指得到具体位置。体检 → ①按层条数与字数、超长清单都看过；②四类问题逐条判过；③改动当轮落库并复验；④报告写清改了几条、为什么保留没改的。

## 9. 索引重建

**什么时候必须重建**：批量改过正文（`memory_update` 只写正文，**不重算向量**）；条目跨库搬过；换 embedding 模型或 dtype；检索突然大面积搜不到（先怀疑索引，别怀疑词）。

用 runtime 的 node（要 `node:sqlite`），别用系统 node：

```powershell
$NODE_BIN = Join-Path $env:DSH_HOME 'dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe'
$mjs = Join-Path $env:USERPROFILE '.agents\skills\memory-collab\scripts\rebuild-index.mjs'
& $NODE_BIN $mjs                                  # 不带参数：重建全局库
& $NODE_BIN $mjs '<工作区>\.dsh-mind\memory.db'    # 工作区库：把 <工作区> 换成实际路径
& $NODE_BIN $mjs '<库>' '<meow-mind 目录>'         # 插件不在默认位置时显式给目录
```

**两条口径抄错就静默搜不到**：①`memory_fts` 的 body 必须走 meow-mind 自己的 `buildBody(title, content, keywords)`（中文 2-gram 滑动、单字保留、英文数字按 `[A-Za-z0-9_.+\-/#@]` 成词、keywords 拼两遍加权、上限 400 token）——按空格切或用默认分词器写进去看似成功，查询时 `ftsQuery` 包成 `"..."` 短语会对不上，返回空且不报错；②`memory_vectors` **先整表 `delete` 再写**，只 upsert 会把已归档条目的旧向量留成孤儿，自检「向量条数 = 活跃条数」永远对不上。

**验收**：末行必须是 `PASS`（`active = fts = vectors`、`异模型 = 0`）；再挑一个「只在重建后才存在」的词跑一次 `memory_search`，命中才算完。只信 PASS 不看检索＝只验计数没验通路。

## 10. 准则文件与生效时机

1. **两份文件分工**：完整版＝全局库样板 `guidelines`（`memory_doc get(name:"guidelines")`，含用户原话、实测数字、工具链细节）；可检索结论在全局库 `rules`（`project='全局'`）；要点版＝`DSH_HOME\AGENTS.md`，每会话注入。口径：结构性内容以样板为准，实测数字以最近一次自检为准，样板与要点版冲突以样板为准。原 `C:\deepseek\共享\agent-准则.md` 已删除，别再往那写。
2. **同构检查**：节数、节序、措辞要对得上；节数以现场数为准——`Select-String -Path $DSH_HOME\AGENTS.md -Pattern '^## '`（2026-11-26 实测九节：零–八）。
3. **注入机制**：内核包 `@deepseek-ai/dsh-agent-instructions`（dsh-base 默认启用，每条链 64 KB、`maxSourceBytes` 1 MB）在第一个请求前把 user-global 链作为 durable baseline 注入一次：先 `$DSH_HOME/AGENTS.md`，再 `~/.agents/AGENTS.md`。project 链靠 `projectRootMarkers`（默认 `.git`）定根；本机 `C:\deepseek\work`、`study`、`deepseek` 都没有 `.git`，靠不住，只用 user 级。
4. **全局 `rules` 与 `AGENTS.md` 不是同一套机制**：`AGENTS.md` 改完在下一次成功文件操作后对新请求生效，`rules` 只在会话开始注入一次。中途新增的 `rules` 不会自动出现——用户问「读到了吗」，必须主动 `memory_search` 或查库确认。
5. **改准则文件的顺序**：先改完整版 → 同步要点版 → 对拍结构（节号、节数、口径）→ 查易腐数字 → 回读行数与字节数 → 需要时当轮留痕。**工作区隔离**：库按工作区一个、互不相通；写给别的工作区的规则写进全局库 `rules` 或 `memory_doc` 样板，别再写本地 md 文件（各工作区读不到、也不随注入生效）；新增共享工具先补完整版，再回填要点版。

**改一条准则前的四个问题**：①全局适用还是单项目（全局 → 两份都动；单项目 → 写该项目 `rules`）；②和现有条目冲突吗（冲突先合并成一条，不要两条并列）；③是可执行判据还是口号（写不出「遇到 X 就做 Y」的不立）；④改完谁来读（别的会话要用，必须落文件加指针）。

## 11. 迁移红线

1. **先分清三个东西**：①工作区库＝`<cwd>\.dsh-mind`（配置 `projectDir`）；②全局库与信箱＝`<globalDir>`（配置 `globalDir`）；③`homeDir`（全局目录覆盖，空＝平台默认，管日志与窗口账本）。三件事，别用错工具。
2. **怎么搬**：库是普通 SQLite，停写 → 复制整个目录（含 `-wal`/`-shm`）→ 改配置项（设置页可改、`volatile`、改完立即生效）→ `memory_home` 确认新路径与新条数。**`memory_home` 只报路径与条数，不替你搬**；不要假定存在某个标记文件（旧文档里的 `home-dir.json` 是历史行为）。
3. **三条红线**：目标非空视为已迁移，绝不覆盖（要不要并先问用户）；旧目录不自动删，删不删由用户确认；搬之前必须停写。**拒绝的路径**：空、相对路径、盘根、主目录本身。
4. **迁移后验收**：`memory_search` 能读新库；`memory_*` 工具都在（插件可能从 `dsh.profile.bundles` 掉出，表现为全部报 unknown tool）。**三查**（条数相同也可能搬错）：按层条数、逐条内容与源库比对、字段级归属分布——漏建 `project` 列时条数全对、归属全空，靠 project 分布才查得出。**迁坏了怎么退**：旧目录没被删（红线 3），把 `globalDir`／`projectDir` 指回旧路径即回滚，回滚前先停写。**动手前说清代价**：体积、要不要重启、旧目录留不留，等用户明确同意；多实例共享同一目录时先提醒对方同步，否则一边搬一边写。

## 12. 常见错误

1. **写错层**：经验写进 `fact`、项目状态写进「全局」；回读时对照 §5 再看一眼。
2. **只 update 不归档旧条**：改结论后旧条还在检索面，两条相反结论同时命中。
3. **并行写同一库**：撞 id、静默丢内容；串行 + 回读。
4. **时间戳写成 17 位微秒**：被当未来时间，天数夹成 0、recency 恒 1，整库时效权重失效；必须毫秒。
5. **凭「应该注入了」回答**：中途新增的 `rules` 不进已开着的会话（§10 第 4 条）。
6. **把「放了很久」当「过时」**：归档判据是有没有后继事实，不是年龄。
7. **拿记忆当技能用**：同一条判据两处都有＝两套真相，按 §7 去重。
8. **在共享面上只改不报**：当轮不写留痕，事后补是欠账（§3 第 7 步）。

## 13. 与 `skill-authoring` 的分工

技能怎么写的完整口径在 `skill-authoring`（description 是路由、正文五段骨架、`SKILL.md` 50–250 行、`references` 每篇 ≤200 行、实测进 `evidence/`）。本技能只管两条自己的约定：①**触发词不重叠**（同一件事别让两个技能都命中，写前看现有技能清单）；②**技能 `author` 手写**（`ZQY-LD` / `ZQY-LB`，不带会话码）。**固化门槛也以它为准**：同一类转换做到**第三次**才写进技能（第一次摸索、第二次确认、第三次才是常驻流程），第二次就固化会写出一堆一次性流程。
