# 05 · 材料：从散件到能查的成品

这一篇管「资料怎么进来」。**工具可以自选**——本篇给的是选路判据与验收标准，不是必须用某个软件。

## 一、先分诊：你的来料是哪一类

| 来料 | 走哪条线 | 成品形态 |
|---|---|---|
| 手机翻拍的投影幕照片（一批几十张） | **照片线** | 一份按页序排好的 PDF |
| 原始 `.ppt` / `.pptx` | **PPT 线** | 每讲一份 PDF，再合并成整份 |
| 扫描版 PDF（整页是图） | **OCR 线** | 有文字层的 PDF + 可检索文本 |
| 矢量 PDF（能选中文字） | **直取** | 保持原样，直接抽文本 |
| Word / Markdown 讲义 | **直入** | 直接导入，不用转 |

**第一件事永远是判有没有文字层**：`doc_info` 看 text density 与 image count。判错方向会白做一夜（把矢量 PDF 当扫描件 OCR，或把扫描件直接抽出一片空白）。

## 二、解析工具自选矩阵

| 输入形态 | 首选 | 备选 | 判据 |
|---|---|---|---|
| 有文字层的 PDF | 任意 PDF 库逐页抽（`doc_text` / `pypdfium2` / `pdfplumber`） | — | 抽出的文字能读，页码对得上 |
| 扫描 PDF / 图片 | `doc_ocr`（本地 MinerU 类引擎） | 在线 OCR、系统自带识别 | 中文通顺、公式左右不颠倒、表格不塌 |
| 公式密集页 | OCR 引擎的公式模式（输出 LaTeX） | 原页截图 + 手工补 | 上下标与分式能对上 |
| `.pptx` 里的公式 | 转 PDF 后再 OCR | 直接读 OOXML 里的公式对象 | 转完公式不丢 |
| Word / Markdown | 直接读 | — | 不用转 |
| 表格式内容（成绩、对照表） | 结构化抽取（对表格专用的工具） | OCR 后人工核 | 列不对齐就是没抽对 |

**每一步都要写「没有 X 用 Y 顶」**：别人机器上不一定有同样的工具，判据比工具名重要。

## 三、三条线怎么走

### 照片线（拍屏幕）

1. **按批归档**：一批一个目录（`照片原件1`…），不要混。
2. **裁切**：去掉桌边、手指、投影幕黑边——只留屏幕内容。批量脚本按包围盒裁，个别歪的手动补。
3. **校色**：投影幕发蓝就做一次白平衡；对比度太低就拉一下，但**不要锐化到出现白边**。
4. **排序**：按文件名或拍摄时间排，**先抽 3 张核对页序**（拍漏、拍重是常态）。
5. **拼 PDF**：一图一页，A4 或原始比例；加页码。
6. **验收**：随机翻 5 页，字能看清、页序连续、没有半张。

### PPT 线

1. **转 PDF**：优先用办公软件自身的导出（保字体与公式）；命令行转换（LibreOffice 等）可能掉字体。
2. **一讲一文件**，文件名带讲次与标题（`第09讲-定态薛定谔方程.pdf`）。
3. **合并**：按讲次顺序合并成整份，加书签（每讲一条，落在起始页）。
4. **验收**：页数 = 各讲页数之和；书签数 = 讲数；`doc_info` 看 Producer 与 Title。

### OCR 线（扫描件）

1. **切分**：单份太大（很多 OCR 服务有几十到几百 MB 的上限）就按 100 页切，**记住每片的起始页**。
2. **OCR**：缓存结果，**不要重复跑**；失败页单独重试，不要整份重来。
3. **拼回**：按片序拼成 1..N 页，`page` 用**原书页码**，不要用片内页码。
4. **验收**：抽 5 页比对原图（中文、公式、表格各看一页）；空页率 < 15%。
5. **页码偏移**：书页与 PDF 页常差一个常数（如书名页、目录不编号），建库时必须在 `rel_path` 或单独字段里说明用哪种页。

## 四、材料就位后的验收

材料按 `04-kb.md` 建成库之后（**建库与三条验收判据都在那一篇**：建库用 `scripts/build_kb.py`，本技能只带这一个建库器；`kb.py` / `kb.cmd` 是使用者自己配的查询 CLI，路径写在 `config.json` 里，技能不附带），**先用下面三条命令验一遍再拿它带学**：

> **`<KB_CLI>` 必须写全路径，或先 `cd` 到它所在目录**。`kb.cmd` 不在 `PATH` 里，直接敲 `kb.cmd status` 会报 `'kb.cmd' is not recognized as an internal or external command`。本机实例：`C:\deepseek\study\_kb\kb.cmd`。

```
<KB_CLI> find "<要讲的章节里的词>"
<KB_CLI> page "<书名的一段>" <页码>
<KB_CLI> status
```

三条依次回答：检索能不能命中、命中条目的章节对不对？取到的那一页是不是真内容（看正文首行）？这门课几篇文档、多少条目、有没有空页？（`--` 在 Windows 命令行里不是注释，别跟在命令后面。）**没配查询 CLI 的**，用 `04-kb.md` 第七节的 SQL 做同样三件事，判据不变。

**判据**：从要讲的章节里挑三个词，三个都能命中，且点开的那一页正文对得上——否则带学时「必须能在资料里找到」这条就做不到。命中但页码偏一章以上，说明页基准没对齐，回上一节第 5 条修。

## 五、材料之间谁说了算

同一件事常有三四种材料在讲，冲突时按这个顺序取证据，**不要按「哪份看着舒服」取**：

| 优先级 | 材料 | 拿它干什么 | 注意 |
|---|---|---|---|
| 1 | 考纲 / 真题 / 老师划的重点 | 定「考不考、考多细」 | 落到**条目与页**，别拿整章当考点 |
| 2 | 教材 | 给定义、推导、标准说法 | 版本要对上，页码要写清 |
| 3 | 课件 / 讲稿 | 给这门课**自己**的讲法与记号 | 记号可能和教材不同，讲的时候要说明 |
| 4 | 习题册 / 笔记 | 补题型与易错点 | 只能当参考，不能当定义来源 |

四条判据：

- **一句结论只能有一个出处**。两份材料说法不同，就明说「教材这么讲、课件那么讲」，并说清以哪份为准（一般是考纲/真题优先）。
- **引文必须能在材料里逐字找到**。找不到就标「材料里没有」，不要用「大意如此」补。
- **哪一级都没有，就写「未覆盖」**——宁肯留白，也别把通用知识冒充成这门课的内容。
- **页码要对得上**：抽出来的文字连同页码一起存，之后引用时指得到具体页。页码错一位，复习时就找不到地方。

## 六、边界

- **不替用户决定要不要入库**：OCR 与建库都费时间，先问「只讲到哪、要不要整本入库」。
- **不猜页码**：拿不准就 `doc_render` 出图看。
- **一次性中间件当场删**（切分片、试验脚本、导出的临时 md），不要留在课程目录里。
- **原件不动**：照片原件、原始 ppt 保留原处；成品另存。
