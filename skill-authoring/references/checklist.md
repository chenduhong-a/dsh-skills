# 交付前清单（反模式 · 清单 · 症状→原因）

> 从 `SKILL.md` 的反模式、交付前清单、症状→原因三部分抽出（2026-11-21 分层时挪出），只在**落盘前**与**排错时**读——写技能的正文不需要它，所以挪出来省每次加载的 token。

## 反模式

- ❌ 把技能当知识库，塞进整本手册
- ❌ description 写成功能介绍，没有触发词与边界
- ❌ 一个技能覆盖「写代码 + 审查 + 发布」
- ❌ 正文重复 frontmatter 已有的信息
- ❌ 用 camelCase 字段名
- ❌ 依赖「模型应该知道」的隐含前提
- ❌ 把密钥、内网地址、个人路径写进技能
- ❌ 只测「能不能跑」，不测「该不该触发」
- ❌ 照抄模板里的具体数值（300 字、5 条、四节）
- ❌ 写到不在扫描根的位置还不声明（写进去等于没写）
- ❌ 把「压到原来 40–60%」当拆分验收标准——降不动的往往是判据
- ❌ 把一次性观测写成绝对断言（「子代理不能再派」「截断在 500 字符」「必须 ≤100 行」）——要么写清取决于什么配置，要么标未实测
- ❌ 脚本留在 `tools\` 根目录、靠作者机器的绝对路径跑

## 交付前清单

- [ ] **路径在扫描根下**（跑过 `SKILL.md` 第 2.1 节的检查）
- [ ] **正文提到的每个路径、脚本、命令都 `Test-Path` / 实跑验证过**（交叉引用不悬空，先把下方「正文提到的东西找不到」挡掉）
- [ ] 目录名 = `name`，合规且与 frontmatter 一致
- [ ] `description` 含触发词与边界，关键信息在前 40 字
- [ ] 字段名全部 kebab-case；带中文标点的描述已加引号
- [ ] 流程类正文有五段（输入 / 步骤 / 停止条件 / 输出格式 / 验收）；判据类不凑五段，但至少有「什么时候停」与「怎么算干对」两张清单
- [ ] 没有通识废话、没有放权句、命令自包含、占位符有来源
- [ ] 主题单一；正文里没有大量只用于复现的实测数字（有则拆 `evidence/`）；超过 250 行或落在 200–250 灰区，已按 `SKILL.md` 第 7 节 ③ 答过「读者要顺序读完吗」（本技能自己也适用：正文行数按这一问定，不钉死数字）
- [ ] 脚本在技能自己的 `scripts/`，常量可被环境变量覆盖
- [ ] 无密钥、内网地址、个人路径（实例路径只在附录）
- [ ] 通过「目录可见 + 触发评测 + 产物对比 + 独立子代理自足性」四级；做不了的级别已标「未执行 + 原因」

## 症状 → 原因

| 症状 | 大概率原因 |
|---|---|
| 完全不出现 | 路径层级错（不在根下第一层）、文件名不是 `SKILL.md`、frontmatter 解析失败 |
| 出现但从不触发 | description 缺触发词，或过于笼统 |
| 总是误触发 | description 没写边界，覆盖面过宽 |
| 触发了但不按步骤做 | 正文是散文而非编号步骤，或缺少停止条件 |
| 长会话后半段失效 | 上下文压缩裁掉了正文，关键约束要在开头复述 |
| 改了没反应 | 改的是 description / 文件名，目录未刷新；或改错了另一个同名技能 |
| 正文提到的东西找不到 | 交叉引用悬空——`references/x.md` 被改名或没一起搬 |
| 换台机器跑不起来 | 脚本里写死了作者路径，或依赖 `node` 在 PATH |
